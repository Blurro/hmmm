CTGP-7 Loader Fixed8: crash 75 repair and current handoff

CRASH 75
The attached dump names the process "loader". ARM11 core 1 data abort:
  PC  0x140066B8
  FAR 0x00000134
  R5  0x00000130
  R6  0x08F00000
  R7  0x00000000
  DFSR 0x00000805
The instruction is E5856004, STR r6,[r5,#4]. It writes the late target-side
installer pointer into the second hook word, site[1], in the ZL installation
path inlined into LoaderDiag_ThreadMain. The local page alias base is zero.
All 96 captured code bytes exactly match Fixed7's ELF, beginning 0x1400665C.

This is a Loader mapping regression before Y releases CTGP. It is separate
from the unresolved original privileged kernel PC-zero crash.

CAUSE AND REPRODUCTION
The inherited free-range finder queried from 0x01000000 but used the base
of the whole free region returned by svcQueryMemory. A free region can
begin at zero, so it could incorrectly select an alias below the search
window. Fixed7 added a second temporary alias while the first remained
mapped. With the first at 0 and the second at 0x1000, adjacent mappings can
coalesce; unmapping the second can then invalidate the first before the
hook pointer write at 0x134.

The new regression executes the actual Fixed7 ELF with containing-region
queries and an explicitly stated coalesced-unmap model. It reproduces the
dump's exact PC 140066B8, write address 134 and value 08F00000. The dump
does not contain the kernel memory-region history, so the precise internal
coalescing sequence is an inference supported by this matching reproduction.
The earlier mocks returned the queried address as the free-region base and
did not model this behavior. Fixed7's passing tests therefore missed it.

FIXED8 CHANGE
Only source/loader_diag.c changes among production source files:
1. Clamp the selected free address to the current search address before
   alignment. Every selection stays in 0x01000000..0x0EFFFFFF. Reject invalid
   zero or oversized requested ranges.
2. For a temporary target-page alias, find three free pages and map only
   the middle one. A free page on each side prevents simultaneous aliases
   created by this helper from becoming adjacent.
In the same reproduction model, aliases now map at 0x01001000 and 0x01003000.
Unmapping the IV alias preserves the mid-hook alias, and ZL completes.

The existing IV repair remains:
  0x07001450: C9A8AD0F -> 30F72D2B
  0x07001D0C: E021C002 -> E51FC8C4
It fixes the checksum-derived first CBC-IV word. The Rosalina scan still
runs. Copied early/late ARM gates remain byte-identical to Fixed6. The
full-page startup fingerprint, same-process check and staged R cleanup stay.
